## 1. The model, in your words

The IIG describes three movements: **SQL Server metadata → UC Delta** (the
metadata rows define every table and pipeline; the UC tables are created from
them — your "DDL"), **Source → Stage** (one row per inbound file into the
stage detail table: `ADLS_DELTA_INGESTION_DETAILS`, + `FILE_ADLS_…` and the
`DATA_QUALITY_RULES` split row) and **Stage → Standard** (one row per table:
`STGDELTA_STDDELTA_INGESTION_DET`).

The agent writes the same cells twice. The **IIG workbook** is the human
handoff: the BSA and engineer review it, and it holds what the client's sheets
hold. **`metadata_inserts.sql`** is the database handoff: one INSERT per IIG
row. The two differ by exactly three rules, stated in the SQL header:

1. **Value map:** `ACTIVE_FLAG` / `ACTIVE_RULE_FLG` `Y` → `S`.
2. **Forced NULL:** columns the framework fills itself — `DAY_OF_SCHEDULE`,
   `UDF2`–`UDF5`, the SLA columns, `CLAIM_TYPE_ID`.
3. **Audit defaults and open cells:** `GETDATE()` / `@RFC_NUMBER`; every open
   cell is a `<<COLUMN#n>>` placeholder (the script will not parse until
   filled).
